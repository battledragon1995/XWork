# BE-013 File Tree — Stage 15 Backend Implementation Plan

**Status:** Backend implementation and automated gates complete; native and
FE-016 acceptance remain pending.

**Goal:** Expose four typed, main-window-only Files commands that browse, filter,
refresh, copy paths and reveal entries in a registered project through real,
bounded, read-only filesystem queries.

**Completion Criteria:**

- Public service and mock-runtime IPC tests prove BE-013 listing, search,
  pagination, fresh ignore rules, project availability, path boundaries and
  link/reparse rules against isolated registered temporary projects.
- The documented root identity, intent resolver and writer-target validation
  contract exists and is tested without implementing file reading or writing.
- Four commands are composed with Projects and the Rust opener adapter; generated
  TypeScript DTO/error output matches Rust on a clean second generation run.
- All Windows automated gates below pass, with Cargo jobs limited to one and
  Rust tests serialized. Native evidence is recorded accurately, including any
  checks deferred until FE-016 integration.
- No source file contents, project mutations, filesystem permissions for the
  webview, migrations, watcher, cache, index or additional Files command is added.

**Architecture:** `app` composes Files with the existing public `ProjectService`.
Files owns path policy, ignore traversal, bounded blocking work and the narrow
native reveal adapter. React receives generated contracts; frontend design,
wrappers and UI implementation remain the subsequent FE-016 work item.

**Tech Stack:** Existing stable Rust 1.98.0 / Edition 2024, Tauri 2.11.5,
Tokio, Serde, ts-rs, tempfile and official Rust opener; exact additions below.

## Execution Decisions

- Add only these complete entries under `[dependencies]`:

  ```toml
  ignore = "=0.4.33"
  base64 = "=0.22.1"
  ```

  `ignore` is pinned by BE-013 and TechStack. `base64` implements the specified
  opaque cursor without a custom codec and already exists transitively in the
  current lockfile. Local registry manifests inspected during planning declare
  MSRV 1.88 / Edition 2024 for ignore and MSRV 1.48.0 / Edition 2018 for base64;
  both fit the pinned Rust 1.98.0. Compilation remains an implementation gate,
  not a result claimed by this metadata check. Retain current versions/features
  of all other dependencies, including opener and Windows filesystem APIs.
- Use URL-safe unpadded base64 of versioned JSON for cursors. Version 1 binds the
  normalized directory and complete last-entry sort key. Validate unknown shape,
  version, field consistency, path grammar and 8 KiB encoded size before use.
  A decoded key is an ordering value only; never join it as a filesystem path.
- Preserve the BE-013 sort tuple: kind rank, lowercase basename, original
  basename bytes, relative-path bytes. Search visits siblings in that order,
  depth-first, without descending links, and sorts retained matches by the same
  tuple before serialization. Stop on the first encountered resource limit;
  201st match gives `ResultLimit`, an unexamined candidate beyond the scan budget
  gives `ScanLimit`, and a branch beyond 128 components gives `DepthLimit`.
  This produces a repeatable partial result without promising a global top-200
  snapshot across an unfinished scan.
- Count inspected candidates before visibility filtering so ignored input cannot
  evade resource budgets. Listing beyond 100,000 direct candidates fails rather
  than returning a falsely sorted page. Root is not a search candidate.
- Ignore handling must implement the documented precedence and nested rules;
  direct-child listing reads only the requested directory plus validated ancestor
  ignore sources inside the project, not a recursive scan to reach that directory.
  A walker adapter may explicitly load checked ignore sources with the public
  ignore matcher APIs when automatic discovery cannot enforce the no-follow rule.
  Disabled global/parent sources must never be read to construct that matcher.
- Reject Windows alternate-stream/device/drive spellings and component aliases
  that do not identify a literal entry under the relative-path contract. Never
  normalize an invalid input into a different accepted path. Root identity follows
  BE-003 comparison semantics; do not import its private path-key helpers.
- Warning count counts issues with saturation; at most 20 unique directory/reason
  pairs are returned in encounter order. Set `warnings_truncated` when a further
  distinct pair cannot be represented; duplicates increment the count without
  creating additional serialized pairs.
- Fixture setup, teardown and explicit external-change injection may mutate only
  owned temporary fixtures. The BE-013 no-mutation criterion applies to the Files
  operation being measured; compare snapshots around each operation separately
  from those deliberate fixture changes.
