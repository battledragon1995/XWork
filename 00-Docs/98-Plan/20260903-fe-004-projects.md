# FE-004 Projects Implementation Plan

**Status:** Implemented

**Goal:** Implement the real `/projects` experience and sidebar project list so
users can view, search, add, rename, pin, open, relocate, and remove registered
projects through the existing `BE-003` contract without changing files inside
their project folders.

**Completion Criteria:**

- `/projects` renders every specified loading, ready, empty, search-empty, and
  failure state, with responsive cards in the exact order returned by
  `list_projects`.
- The persistent sidebar uses the same unfiltered project snapshot as the page,
  exposes the shared Add Project flow, and never creates duplicate listeners or
  native folder pickers when both consumers are mounted.
- Search, add, rename, pin, open-folder, locate-folder, impact inspection, and
  removal follow the generated `BE-003` DTO/error contract, including stale
  request protection, explicit confirmation, focus restoration, and all
  documented recovery actions.
- Removing a project deletes only XWork metadata. A targeted Windows smoke check
  proves that the real picker and file manager work and that the project folder
  and its files remain untouched.
- All focused tests, repository-wide frontend and Rust quality gates, production
  frontend build, and Windows Tauri build pass without changing Rust, generated
  bindings, capabilities, or Tauri configuration.

**Architecture:** `src/lib/ipc/projects.ts` remains the sole frontend adapter to
the existing Projects commands and event. A feature-local Zustand store owns one
unfiltered backend snapshot, one shared Add Project lock, consumer counting, and
exactly one event/focus subscription; route-local hooks own the debounced search
snapshot and project action/dialog state. `src/app/` imports only the public
`ProjectsRoute` and `SidebarProjectList` entries, while Rust remains responsible
for persistence, filesystem inspection, native pickers, the operating-system
opener, and removal rules.

**Tech Stack:** React 19.2.8, TypeScript 7.0.2, React Router 8.3.1, Zustand
5.0.15, Tauri API 2.11.1, Tailwind CSS 4.3.3, shadcn/ui CLI/source 4.20.0,
Radix UI through the existing `radix-ui` 1.6.7 package, Lucide React 1.39.0,
Vitest 4.1.11, and Testing Library.

## Scope

**In Scope:**

- The `/projects` page header, count summary, backend search, responsive card
  grid, first-load/refresh/empty/failure states, and page-level action errors.
- The real unfiltered project list in the expanded sidebar, its loading, empty,
  and failure states, current-route marker, project navigation, and Add Project
  entry point.
- A feature store shared by the page and sidebar, with consumer reference
  counting, one `projects://changed` listener, one browser `focus` listener,
  stale-result rejection, retained data during refresh, and one shared picker
  lock.
- Add, rename, pin/unpin, open-folder, locate-folder, impact inspection, and
  confirmed remove flows through the existing generated Projects contract.
- The reusable project card, actions menu, rename dialog, remove dialog, error
  copy mapper, project hooks, `Input` source component, and warning color tokens
  named by `FE-004`.
- Accessibility and keyboard behavior for icon-only controls, menu/dialog focus,
  local `Esc`/`Enter` behavior, and the documented content Tab order.

**Out of Scope:**

- The `/projects/:projectId` Project Overview, `open_project`, `get_project`,
  Git branch/status, changed-file counts, session counts, and sidebar session
  rows (`BE-004`, `BE-005`, `FE-005`, and `FE-006`).
- Creating folders, cloning repositories, Git mutations, unified search,
  drag-and-drop ordering, bulk removal, persisted webview search/layout state,
  dark theme, and font-size settings.
- Any Rust, migration, generated binding, `src-tauri/capabilities/main.json`,
  `src-tauri/tauri.conf.json`, package manifest, or dependency change.
- Global keyboard shortcuts, automated desktop end-to-end tests, and macOS
  validation before release preparation.

## Global Constraints

- Write code, identifiers, and code comments in English; initial UI copy must be
  English and match `FE-004` exactly.
- React owns presentation and temporary UI state. Rust owns project data,
  persistence, filesystem checks, native picker/opener behavior, and business
  rules.
- Every backend call passes through `src/lib/ipc/`; components never call Tauri
  or operating-system APIs directly.
- `src/app/` may import only `ProjectsRoute` and `SidebarProjectList` from this
  feature. `src/features/projects/` must not import another feature's
  implementation, and `src/lib/` must not depend on `src/features/` or
  `src/app/`.
- Use `ProjectDto`, `ProjectFolderSelectionDto`, `RemoveProjectImpactDto`,
  `RemoveProjectResultDto`, `ProjectChangedEventDto`, and `ProjectsError` from
  `src/bindings/projects/projects.ts`; never hand-write or manually edit a
  backend DTO/error mirror.
- Treat `projects://changed` only as an invalidation signal. Re-query the backend
  and do not apply its `change` or project ID directly to an in-memory list.
- Keep backend ordering unchanged: pinned projects first, then `addedAtMs` and
  ID as already established by `BE-003`. Do not sort or add a Pinned divider in
  the frontend; key cards and sidebar rows by `project.id`.
- The store holds only the unfiltered `listProjects()` result. A non-empty route
  search calls `listProjects(search)` after 200 ms; it never filters the store
  snapshot or changes the sidebar.
- Sanitize a submitted search by removing control characters, truncating to 256
  Unicode scalar values, and trimming its ends. Preserve the unsanitized text in
  the visible input.
- Keep the last successful list/search result rendered during refresh and ignore
  any result older than the latest request or published after its owner unmounts.
- The first consumer creates exactly one project-event subscription and one
  browser-focus subscription. The final consumer removes both, including a
  listener whose asynchronous registration completes after release.
- `beginAdd` is the sole duplicate-picker guard shared by the page and sidebar.
  A cancellation changes no data, shows no error, and returns focus to the exact
  initiating control.
- Never call `open_project`. Card and sidebar navigation go directly to
  `/projects/:projectId`; only the later Project Overview slice owns last-opened
  tracking.
- Never call `removeProject` with `confirmed = false`. Inspect impact first and
  use only the returned impact or a later `confirmationRequired.impact` payload
  to render removal facts.
- Disable only the card whose operation is pending. Do not optimistically mutate
  the project list; explicitly refresh after command success as protection
  against a failed backend event emission.
- Keep branch, Git, changed-file, and session text completely absent from this
  slice. Do not render disabled placeholders for later capabilities.
- Icon-only `More actions`, sidebar Add Project, and Clear search controls have
  hover/focus tooltips. Non-interactive pinned and unavailable glyphs instead
  carry the exact visually hidden labels `Pinned` and `Folder unavailable`.
- Add `src/components/ui/input.tsx` through the component CLI as source owned by
  this repository; add no dependency or manifest change. Project-specific
  styling remains in the feature callers.
- Add only `--color-warn-surface: rgba(232, 165, 90, 0.22)` and
  `--color-warn-ink: #7a4a12` to the shared token source. Feature code contains
  no hard-coded colors and introduces no motion.
- Every new function, component, hook, callback, helper, and test has a short
  purpose comment. Add concise reasoning comments around request tokens,
  consumer counting, late listener cleanup, and duplicate-operation locks.
- Tests replace the IPC adapter, event registration, browser focus listener,
  navigation, and timers with local doubles. They must not access real app data,
  projects, folders, native dialogs, or operating-system resources.
- Develop and verify on Windows. Do not add or run an automated desktop
  end-to-end suite; defer macOS checks until release preparation.

## Assumptions, Risks, and Blockers

**Assumptions:**

- `BE-003` and its generated `src/bindings/projects/projects.ts` are implemented
  and current. This plan consumes their public command/event contract without
  changing it.
- `FE-001` and `FE-002` are implemented. The `/projects` route is still an
  `AreaPlaceholder`, the sidebar still contains the documented empty copy, and
  the existing Projects IPC adapter currently covers only list, add, and event
  subscription.
- Existing `Button`, `Dialog`, `DropdownMenu`, `Tooltip`, sidebar primitives,
  CSS tokens, and Lucide icons can express the feature without changing their
  behavior. Only the specified copied `Input` source and two warning tokens are
  missing.
- The shadcn/ui CLI/source version remains 4.20.0, whose `new-york-v4` registry
  compatibility with this exact React/Radix stack was already verified by the
  implemented FE-001 plan on 2026-09-02.
- At Stage 4, `NoProjectRuntimeGuard` normally returns zero removal counts, but
  the dialog must support non-zero facts now for Stage 8 reuse.

**Risks:**

- Concurrent event/focus/manual refreshes could let an older list or search
  response overwrite newer state. Tasks 2 and 3 use independent monotonically
  increasing request tokens and deferred-promise tests to prove last-request
  wins.
- Tauri event registration is asynchronous and may finish after the final
  consumer releases the store. Task 2 records the released generation and
  immediately invokes any late unlisten callback; tests control registration
  completion explicitly.
- Add Project exists in two simultaneously mounted components. Task 4 puts the
  lock in the shared store and tests near-simultaneous calls from both entry
  points against one deferred `addProject` promise.
- A mutation may succeed even if backend event emission fails. Task 5 requests
  an explicit store refresh after every successful mutation, rather than
  relying only on `projects://changed`.
- Pinning reorders a focused card and removal destroys its trigger. Tasks 5 and
  6 retain stable project keys and explicit trigger/search refs, then test focus
  after reorder, dialog close, cancellation, and removal.
- Browser `focus` may not fire when the main window is restored from the tray
  because `BE-001` exposes no explicit “main window shown” event. The manual
  check records actual Windows behavior; this plan does not invent a backend
  event or promise stronger behavior than the source contract provides.
- UI tests could accidentally depend on real timers or global Zustand state.
  Tasks 2–6 use fake timers only inside isolated tests and call the feature's
  reset helper before each test.

**Blockers:** None.

## Deviations and Decisions

- `src/features/projects/project-error-copy.ts` was created in Task 2 instead of
  Task 3. The store needs the two list-failure strings, and `FE-004` names that
  module as the single owner of the feature's error copy, so creating it early
  keeps one owner rather than duplicating `INTEGRATION_MESSAGE` in the store and
  then moving it. Task 3 extended the same file with the add, action, folder and
  availability tables as planned.
- `ProjectActions` gained one method the documented shape omits:
  `retryFailure(): Promise<void>`. The error table requires `Try again`,
  `Locate folder…` and `Open folder` recovery controls, but
  `ProjectActionFailure` carries only the operation to repeat, not the project it
  happened to, so the page line has no way to reach the target without it. The
  hook remembers the last target and repeats exactly the named operation.
- The page title renders as `h1`, not the `h2` the `FE-004` component table
  names. `FE-001` and `FE-002` give every route one `h1`, and the shell provides
  no page-level heading, so an `h2` here would leave the document outline without
  a top-level heading. The visual treatment is unchanged: `display` font at
  `28px`.
- Focus restoration after a dialog closes lives in `projects-route.tsx`, not in
  the dialog components. The dialogs are fully controlled: the same state change
  that closes them also unmounts their content, so Radix's own close-time focus
  restore never runs. The route already owns the card trigger refs and the search
  input ref, which is also the only place that knows a successful removal must
  send focus to search instead of back to a card that no longer exists.
- The page action-error line clears when the next operation starts and when the
  user dismisses it, but not on a successful list refresh. `projectNotFound` and
  `projectUnavailable` both refresh the list themselves as their documented
  recovery, so clearing on refresh would erase those messages in the same frame
  they appeared.
- The action and Add Project error lines carry a text `Dismiss` control rather
  than an icon-only close button, so the slice keeps exactly the three icon-only
  controls `FE-004` requires tooltips for.
- Removal facts use singular wording at a count of one — `1 session will be
  stopped first.`, `1 running process will be stopped.`, `1 file with unsaved
  changes will lose them.` — matching how the count line handles `1 project`.
- The shell tab order gained two stops inside the sidebar: the `Add Project`
  action and the project rows, between `Calendar` and `Settings`.
  `src/app/app-shell.test.tsx` records the new order; every other `FE-001`
  behavior is unchanged.
- `src/app/app-shell.test.tsx` and `src/app/app-sidebar.test.tsx` now mock the
  Projects IPC boundary. The sidebar block queries the backend, so without the
  mock those shell cases would depend on a real `invoke` rejection.
