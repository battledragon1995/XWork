# FE-006 Session Implementation Plan

**Status:** Implemented — every automated gate passes; the manual Windows smoke
checklist in Task 9 Step 3 is still outstanding because it needs an interactive
`pnpm tauri dev` session.

**Goal:** Implement the complete FE-006 session lifecycle on top of the
already-implemented BE-005 and BE-006 contracts: create, open, rename, and
delete runtime sessions; choose or recheck a CLI tool; and keep the session
route, project overview, sidebar, and breadcrumb synchronized during the
current application run.

**Completion Criteria:**

- Both `New Session` entry points on `/projects/:projectId` create exactly one
  runtime session and navigate to `/sessions/:sessionId`; unavailable projects
  cannot start a session and explain why.
- The session route renders loading, missing, failed, empty-session tool
  picker, and nonempty-session placeholder states; it observes only the active
  session and exposes rename/delete throughout this FE-006 slice.
- Tool cards preserve backend catalog order, support in-memory recent usage and
  local number keys, distinguish unavailable tools without relying on color,
  recheck availability, and select one tool without starting a process.
- Rename/delete flows implement every FE-006 error branch, including refreshed
  `confirmationRequired` impact, and synchronize the route, overview,
  breadcrumb, and sidebar without handwritten backend state.
- Sidebar rows expose all six session states with accessible text, remain under
  the correct expandable project, and converge after ordinary, stale, or
  skipped runtime events.
- All focused tests and frontend quality gates pass on Windows, the production
  frontend build succeeds, and the targeted `pnpm tauri dev` smoke check proves
  the real multi-project workflow. No Rust, generated binding, capability,
  Tauri configuration, package manifest, or persistent web storage changes are
  introduced.

**Architecture:** Add a single typed Sessions adapter under `src/lib/ipc/`, a
retained session-summary store owned by `src/features/sessions/`, route-local
detail/tool/lifecycle hooks, and pure shared session copy/status helpers under
`src/lib/utils/`. The app composition root joins session-owned sidebar/route
entries to the project-owned overview; the two features never import each
other's implementation and independently query the backend. React owns only
presentation and process-local UI state, while BE-005 remains authoritative for
runtime sessions and BE-006 remains authoritative for CLI availability.

**Tech Stack:** React 19.2.8, TypeScript 7.0.2, React Router 8.3.1, Zustand
5.0.15, Tailwind CSS 4.3.3, existing source-owned shadcn/ui primitives over
`radix-ui` 1.6.7, Lucide React 1.39.0, Tauri API 2.11.1 consumed only through
`src/lib/ipc/`, Vitest 4.1.11, Testing Library 16.3.3, and the generated BE-003,
BE-005, and BE-006 TypeScript contracts. No npm or Cargo dependency is added.

## Global Constraints

- Write code, identifiers, UI text, and code comments in English. Keep Markdown
  UTF-8 and preserve the Vietnamese source specifications.
- Every function, method, callback, helper, component, and test added or changed
  has a short purpose comment. Add concise reasoning comments for revision
  ordering, stale-request suppression, delayed listener cleanup, focus refresh,
  observed-session teardown, and repeated close confirmation.
- React owns presentation, focus, pending operations, dialog state, the retained
  backend snapshot reference, and the process-local recent-tools list only.
  Rust owns runtime sessions, business rules, CLI resolution, filesystem/OS
  access, and close impact.
- Every backend call/event goes through `src/lib/ipc/`. Components and hooks do
  not import Tauri APIs, touch the filesystem/database/process environment, or
  call `invoke`/`listen` directly.
- Consume all DTO/error/event types from generated bindings verbatim. Never edit
  `src/bindings/` or declare handwritten mirrors of the public backend
  contract.
- `src/app/` may import the public session entries needed for composition.
  `src/features/projects/` and `src/features/sessions/` must not import each
  other's implementation. Shared pure semantics proven by both consumers live
  under `src/lib/utils/`.
- `src/features/sessions/` must read `getCliProfiles`, `checkCliProfile`, and
  `onCliProfilesChanged` directly from `src/lib/ipc/cli-profiles.ts`; it must not
  import `src/features/settings/cli-profiles-store.ts`.
- Preserve backend order for `CliProfilesSnapshotDto.profiles` (Codex, Claude,
  Terminal, then custom). Only the separate `Recently used` block is promoted;
  `All tools` remains unchanged and may repeat those profiles.
- Compare decimal revision strings as non-negative integers by normalized
  length and lexical order; never convert BE-005 `u64` revisions to JavaScript
  `number`. Ignore revisions at or below the applied revision and reload after
  any gap larger than one.
- Treat `sessions://runtime-changed` summaries as committed data and
  `cli-profiles://changed` as invalidation only. A listener registration that
  resolves after its final consumer left must immediately call its returned
  unlisten function.
- A session name is trimmed, contains 1–80 Unicode scalar values as counted by
  `Array.from`, and contains no control character. Duplicate names are valid;
  BE-005 remains authoritative.
- Render each status dot with a textual label. Sidebar text may use `sr-only`,
  but color is never the sole status signal. Long names and paths are one-line
  ellipses with the full value in `title`.
- Local number keys apply only while the tool picker owns focus context. Ignore
  modified keys, text-entry targets, composition, repeats while an operation is
  pending, and numbers outside the visible card set. Available cards activate;
  unavailable cards receive focus only.
- At most one create request, one tool selection, or one lifecycle mutation per
  owning hook may be active. Checks are tracked by profile ID so separate tools
  can be checked independently while duplicate checks are suppressed.
- `setObservedSession(sessionId)` is best-effort on route entry and
  `setObservedSession(null)` is best-effort exactly once on route exit/session
  change. Window hide/restore does not produce another observation command;
  window focus only refreshes snapshots.
- Tests replace IPC adapters, event registration, navigation, and time with
  local doubles/controlled promises. They dispatch JSDOM focus/keyboard events
  and never read or write real app data, projects, CLI installations, native
  dialogs, processes, credentials, or persistent browser storage.
- Develop and validate only on Windows. Do not add or run automated desktop
  end-to-end tests; use the targeted manual `pnpm tauri dev` checklist for the
  integrated native workflow.

## Assumptions, Risks, and Blockers

**Assumptions:**

- Roadmap Stages 4, 5, and 7 plus backend portion of Stage 8 are implemented in
  the current repository. BE-005 commands/events and BE-006 catalog commands/
  events are registered for the `main` window, and their generated bindings are
  current.
- `FE-001`, `FE-004`, `FE-005`, and `FE-013` are implemented as currently
  present: the session route still contains an `AreaPlaceholder`, the project
  sidebar has no child-row slot, Project Overview shows an intentionally inert
  `New Session` action and no session block, and the CLI Profiles adapter/page
  already support catalog reads and checks.
- `create_session` and `select_session_tool` return full
  `SessionDetailDto` snapshots; successful mutations also emit committed
  runtime events. The returned detail updates the initiating view immediately,
  while events converge independent readers.
- `SessionRuntimeEventDto.revision` is one process-global monotonically
  increasing BE-005 revision. A reader that starts without an event revision
  uses its full `list_sessions` result as a baseline and accepts the next event;
  once a revision is known, it can detect later gaps.
- The existing `Button`, `Input`, `Dialog`, `DropdownMenu`, and `Tooltip`
  primitives plus Lucide icons cover FE-006 without adding or changing a shared
  primitive.
- FE-007 will replace only `SessionWorkspacePlaceholder` and may remove the
  temporary session header for sessions with tabs; FE-006 does not speculate
  about the eventual pane implementation.

**Risks:**

- Three independent session readers can drift after an event race or dropped
  listener. Tasks 2, 4, and 5 use stale-request tokens, monotonic revisions,
  full refresh on revision gaps/focus, and mutation-returned snapshots; their
  tests hold promises and inject out-of-order events.
- Route teardown can clear observation for a newly mounted session if an older
  asynchronous cleanup wins. Task 5 scopes the enter/leave sequence to the
  route effect instance and tests rapid `sessionId` replacement with controlled
  promises.
- A profile can change between catalog render and tool selection. Tasks 6–7
  treat BE-005 errors as authority: missing profiles trigger catalog refresh,
  unavailable profiles receive an immediate temporary marker plus a check, and
  `sessionNotEmpty` refreshes route detail without surfacing a false failure.
- Rename/delete UI exists in two features and can diverge. Task 1 centralizes
  all pure validation, classification, status, and impact copy; Tasks 4–5 keep
  only feature-local JSX/focus ownership duplicated and test both consumers.
- Expanding project rows while the current route changes can collapse the
  active session out of view. Task 3 keeps explicit user expansion in local
  state but forces the active project open and tests pointer, keyboard, and
  navigation transitions.
- Large impact label arrays and long Unicode names can break layout or report
  wrong counts. Task 1 caps displayed labels at five while retaining backend
  counts and tests scalar-value boundaries; presentation tests assert ellipsis,
  titles, singular/plural copy, and `+{n} more`.

**Blockers:** None. FE-006 records no open questions, and all required generated
contracts and prerequisites exist in the repository.

### Recorded during implementation

1. **Focused test command.** `pnpm test -- <files>` runs the whole suite under
   this pnpm version, because pnpm consumes the `--`. Every focused run used
   `pnpm test <files>` instead, which does filter. No plan intent changed.
2. **New shared file `src/lib/utils/session-revision.ts` (plus its test).**
   Three independent readers compare BE-005 revisions: the sessions store, the
   overview hook and the session route. Two of them live in features that must
   not import each other, so the decimal-string arithmetic became a shared pure
   helper rather than a third copy. `src/lib/utils/session-revision.test.ts` is
   a 23rd target in the slice-wide run.
3. **Sessions-local `CliProfilesFailure`.** `ToolCatalogData` names this type,
   but the existing one lives in `src/features/settings/cli-profile-error-copy.ts`
   and the feature boundary forbids importing it. The picker only reads and
   re-checks, so `use-tool-catalog.ts` declares the two-operation subset it
   actually needs.
4. **`use-project-sessions.ts` holds its state in one module-level store.** The
   header's `New Session` and the empty state's `New Session` are two mounted
   entry points that must share one create lock, one query and one listener —
   the same reason `projects-store` owns the Add Project lock. The hook takes an
   options object (`useProjectSessions({ projectId, onCreated, ... })`) because
   only the route knows where a create should lead.
5. **`projectUnavailable` on create shows no separate failure line.** The
   refreshed `Unavailable` banner already states
   `Sessions cannot start until the path is valid again.`; adding a create
   failure with the same classified message printed the identical sentence
   twice. The create flow now only asks the route to re-read the metadata.
6. **`SidebarProjectList` renders its expander only with a slot.** Without
   `renderSessionRows` the block keeps the exact pre-FE-006 behavior. With one,
   the expander precedes the project name in the Tab order, which required
   updating the tab-order case in `src/app/app-shell.test.tsx` — a file the plan
   did not list, changed only for that expectation.
7. **`src/app/app-sidebar.tsx` owns the session snapshot's lifetime.** It
   acquires the store while the `Projects` block is rendered or the current
   route is a session route, and the breadcrumb only subscribes, as Task 8
   requires. Acquiring on a session route as well is what keeps the three-level
   crumb correct even while the sidebar is collapsed; icon mode with no session
   open still releases both listeners.
8. **Dialog focus restoration goes through Radix.** Both rename and both delete
   dialogs take an `onClosed` prop invoked from `onCloseAutoFocus` with
   `preventDefault`. The menu item that opened the dialog has already unmounted
   by then, so Radix would otherwise restore focus to the document body instead
   of the control the user pressed.
9. **The unavailable tool card is a `<fieldset>`.** The repository lint rule
   `a11y/useSemanticElements` rejects `role="group"` on a `div`. A `fieldset`
   carries that role natively and is what the card is: a container for the two
   controls that can resolve its state, not an action of its own.
10. **The session route renders nothing while its session is missing.** The
    navigation happens in an effect; returning `null` for that one phase keeps
    the route from flashing `XWork couldn't open this session.` on the way out.
11. **Pre-existing flaky tests.** Before this slice, a full `pnpm test` on
    `main` failed four cases that pass in isolation
    (`src/features/projects/rename-project-dialog.test.tsx`, three cases, and
    `src/features/settings/settings-terminal-profiles-route.test.tsx`, one
    case). They exceed the default 5 s Vitest timeout while typing with
    `userEvent` under full-suite load. They are unrelated to FE-006 and were
    left untouched; the final full run reported all 1595 tests passing.
