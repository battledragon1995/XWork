# FE-019 Notes Implementation Plan

**Status:** Implemented; all automated Windows gates passed; native verification pending.

**Goal:** Deliver the FE-019 part of roadmap stage 18 with real Notes IPC, revision-safe autosave and Notes integration into Home, Project Overview and Unified Search.

**Completion Criteria:**

- The five Notes wireframe states work against BE-016: create/edit, search/project/pin filters, Archive and Trash including explicit permanent deletion and confirmed Empty Trash.
- Component tests demonstrate one create per acknowledged draft, serialized autosave, conflict/transport recovery, IME admission, no stale publication after maintenance, and no silent loss on ordinary route changes.
- Home pinned/recent, project linked notes/New note and Search active/archived/stale targets are connected; existing Home/project/search behavior remains covered.
- All automated Windows gates below pass. Native checklist entries retain actual evidence or an explicit pending limitation; automated success does not claim native verification.
- FE-020 embedded Home composer remains a separate stage-18 deliverable. Completion of this plan alone does not complete all of stage 18.

**Architecture:** React owns transient drafts and presentation; BE-016 owns records, validation, ordering, lifecycle and revisions. A single NotesProvider retains one unfinished edit across routes; narrow wrappers consume generated DTOs. App composition injects Notes into aggregate features without cross-feature implementation imports. Only pure GFM rendering is extracted into a component with two actual consumers, Files and Notes.

**Tech Stack:** Existing React/TypeScript, CodeMirror, react-markdown/remark-gfm, React Router, Tauri invoke/listen, Vitest/Testing Library and Rust contract tests. No dependency installation or manifest changes.

## Assumptions, Risks, and Blockers

**Assumptions:**

- The user delegated material design decisions, now recorded in FE-019; no unresolved specification question remains.
- BE-016 generated commands and error/event contracts are already registered. No backend change is needed for these UI capabilities.
- Existing manifest entries are reused unchanged. Relevant exact entries are `"@codemirror/state": "6.7.4"`, `"@codemirror/view": "6.43.11"`, `"@codemirror/commands": "6.11.0"`, `"@codemirror/lang-markdown": "6.5.2"`, `"react-markdown": "10.1.0"`, `"remark-gfm": "4.0.1"`, `"react": "19.2.8"`, `"react-router": "8.3.1"`, `"@tauri-apps/api": "2.11.1"`. They are present in package.json and lockfile after FE-018; no new compatibility selection is delegated to the implementer.

**Risks:**

- A create transport failure has no idempotency token. Preserve the draft, ask the user to inspect refreshed Notes, and never silently replay create (Task 2).
- Project removal unlinks Notes without increasing their revision or emitting a Notes event. Subscribe to canonical Projects invalidation and re-read snapshots (Tasks 2–4).
- Search guard currently disables both File and Note targets. Enable only Note with `getNote` revalidation; retain existing File behavior (Task 5).
- Existing Home gates Welcome only on Projects. Note presence must include all lifecycle counts; an error must not impersonate empty state (Task 5).
- Native tray Quit without a session can exit before unacknowledged autosave. This plan does not change lifecycle backend or promise crash/force-exit recovery. Preserve route lifetime, flush on hidden best-effort, show Saved only on acknowledgement, and record the native limitation faithfully.
- App Data provider is separate from Notes provider. Compose public barriers at app level and mount Notes above DataManagementHost, without importing Settings from Notes (Tasks 2 and 5).

**Blockers:** No implementation blocker. Native smoke tools/environment are not currently available; those checks remain pending until a human can operate an isolated Windows VM/Sandbox/test account. Do not invent an app-data override or report build success as smoke success.
