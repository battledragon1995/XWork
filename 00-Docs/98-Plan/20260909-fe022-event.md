## Assumptions, Risks, and Blockers

**Assumptions:**

- BE018 and FE021 are shipped. Generated `src/bindings/calendar.ts` exposes all required payloads; no binding generation changes are needed.
- Controlled React forms are sufficient and match existing shipped forms; React Hook Form/Zod listed as target stack are not installed and will not be added for this feature.
- Drafts are manually saved, not durable. Explicit Cancel/Close asks before discarding dirty input; maintenance/Quit retires drafts under FE021's existing boundary. The form states this behavior.
- Backend permits no reminders despite the requirements' illustrative wording; FE022 adopts 0–16 with one 10-minute reminder by default.

**Risks:**

- Native event may arrive before command acknowledgement; Task 3 protects in-flight edits and refreshes on success without requiring event delivery.
- A transport failure may conceal a committed create; Task 2 blocks automatic/resubmit retries for unknown outcomes and directs the user to check Calendar.
- Focus re-read must not overwrite dirty state or create false conflicts for the same revision; Task 3 verifies both paths.
- Time conversion may corrupt all-day/timezone semantics; Task 1 tests date-only conversion and base DTO mapping without JS recurrence or DST business resolution.
- Native API is disabled in this session. Manual Windows smoke remains pending and cannot be counted as passed.

**Blockers:** None for source implementation and automated verification. Native smoke requires an available interactive Windows control surface.
