## Scope

**In Scope:** Month and keyboard day selection, 1-day agenda, 14-day Upcoming, read-only detail, project labels, Home/Project projections, true Search event activation, narrow IPC wrappers, optional date-prefill create callback, regression tests.

**Out of Scope:** Event mutations/form/delete confirmation (FE022), scheduler/Missed/sent/snooze/dismiss/notification visibility (BE019/Stage21), new Rust commands, backup changes, dependency changes, desktop E2E and macOS verification.

## Global Constraints

- React owns presentation and temporary UI state.
- Rust owns OS access, persistence, terminal processes, and business rules.
- Frontend features do not import implementation from other features.
- Generated bindings under `src/bindings/` are not edited manually.
- Write code, identifiers, and code comments in English.
- The initial UI language is English.
- Every function, method, callback, test, and helper must have a short comment describing its purpose.
- Do not add or run automated desktop end-to-end tests.
- During development, build and test only on Windows.

Markdown is UTF-8. Use current manifest/lockfiles; no library is required for presentation-only Gregorian date arithmetic. All tests mock narrow IPC/listeners and use isolated data, controlled promises and Vitest fake time; never invoke real app-data operations. Do not mutate global process environment for concurrent tests. Date/Intl behavior is controlled through test-local stubs with restoration.

## Assumptions, Risks, and Blockers

**Assumptions:** BE018 is committed and gates passed. User authorized autonomous design decisions and implementation, no review stage. FE021 design is now written and has no open questions. FE022 follows immediately using the same Calendar detail owner.

**Risks:** Viewer dates and all-day dates must not drift through UTC conversion (Task 1). An event invalidation can race initial subscription/read or reset (Task 2). Search may target an event outside the current range (Task 4). Upcoming is not an all-history presence API; render a Calendar projection next to Welcome without inferring global emptiness (Task 4).

**Blockers:** None for implementation. Native smoke is unavailable in this session because native tools are disabled; document this verification limitation.
