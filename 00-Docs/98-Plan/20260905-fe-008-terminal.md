# FE-008 Terminal Implementation Plan

**Status:** Implemented and automated verification complete; native Windows smoke pending

**Goal:** Replace the Sessions terminal placeholder with a working WTerm/Ghostty terminal backed by the existing Rust PTY runtime, including retained history, find, clipboard and web links.

**Completion Criteria:**

- A selected tool launches once after measurement; input/output/resize work across one to four panes and background sessions.
- History survives route changes, Clear Screen and closed-tab reopen; stopped terminals remain readable without respawning.
- Clipboard and HTTP/HTTPS links use the three scoped Rust commands defined in BE-007; generated bindings match Rust.
- Every FE-008 completion criterion and all automated Windows gates pass. Record native smoke evidence separately and do not claim checks that were not performed.

**Architecture:** A root TerminalProvider owns the terminal registry, WTerm instances, core memory, raw Channels and transport queues independently of pane DOM lifetime. The app composition layer supplies a render slot to Sessions; features do not import each other's implementation. Rust retains PTY ownership and provides clipboard/opener adapters behind narrow main-only commands.

**Tech Stack:** React 19.2.8, TypeScript 7.0.2, Vite 8.2.2, WTerm/Ghostty 0.3.4, Tauri 2.11.5, stable Rust 1.98.0 Edition 2024, Vitest/Testing Library and Rust integration tests.

## Assumptions, Risks, and Blockers

**Assumptions:**

- The user approved complete in-memory history until disposal, Clear Screen retaining history, and Rust clipboard plus user-activated HTTP/HTTPS links. The user additionally authorized this plan and its implementation by one `gpt-5.6-sol` agent with `high` reasoning.
- BE-007's six PTY commands are implemented. Session panes still display deferred terminal content. WTerm has not been installed.
- Task paths below are drawn from the feature file table; no scaffold beyond those files is needed.

**Risks:**

- WTerm 0.3.4 calls core.init during initialization and falls back to local echo without onData. Task 1/3 must prove one initialization and persistent instance ownership.
- Ghostty history budget is bytes, not lines; the maximum u32 budget avoids a small artificial application history cap but does not remove WASM/RAM limits. Task 1 verifies retention before building dependent UI. Do not silently fall back to bounded history or claim unlimited physical memory.
- Clear Screen, core-derived colors, alternate-screen history and native IME are compatibility-sensitive. Validate against the exact package, not newer online API signatures. Do not call nonexistent dispose/search/clear APIs.
- A raw Channel may precede its invoke result or deliver callbacks out of order; Task 3 tests this explicitly.
- Native smoke tools may be unavailable. Complete all independent implementation and automated gates, then report the exact remaining manual scenarios; do not invent evidence or mark the whole slice complete.

**Blockers:** None known at planning time. Stop dependent work and report any demonstrated dependency incompatibility that changes the agreed behavior; keep independent tasks moving.

## Deviations and Decisions

- The user explicitly requested one `gpt-5.6-sol` implementing subagent at `high` reasoning, with the parent only coordinating and not reviewing the result. Do not delegate further.
- Product decisions are recorded in FE-008 and the BE-007 supplement. The old BE-007 implementation plan is historical and is not revised.
- WTerm 0.3.4 calls `core.init` from `WTerm.init` and GhosttyCore has no `dispose` method. The implementation therefore owns one persistent WTerm instance per registry entry, supplies `onData` before initialization to disable fallback echo, and releases the WTerm plus all core references only on authoritative disposal.
- Clear Screen snapshots interpreted primary-screen history in frontend RAM, then applies local `CSI 2 J` plus cursor-home to WTerm. It never emits PTY input and does not use the prohibited `CSI 3 J` or a renderer reset.
- The first unconstrained full Rust test attempt exhausted the Windows paging file with `os error 1455`. After removing only rebuildable Cargo artifacts, the exact suite passed with `CARGO_BUILD_JOBS=1` and `cargo test -j 1`; final Clippy and Tauri build also used one Cargo job. No paging-file or machine configuration was changed.
