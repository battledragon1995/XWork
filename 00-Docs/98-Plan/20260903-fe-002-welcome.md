# FE-002 Welcome Implementation Plan

**Status:** Implemented

**Goal:** Implement the `/` route so it renders the documented first-run Welcome
experience when no projects exist, opens the real `BE-003` folder picker through
`add_project`, navigates to the selected or existing project, and switches
between Welcome and the Stage 4 Home placeholder as project data changes.

**Completion Criteria:**

- A clean database opens `/` on the responsive Welcome screen from
  `02-AppShell.html#welcome`, while one or more projects render the unchanged
  `Home` / `This area arrives with FE-003.` placeholder.
- `Add Project` handles cancellation, selection, every documented retryable and
  integration failure, duplicate-project navigation, duplicate clicks, and focus
  restoration exactly as specified by `FE-002`.
- The route refreshes project presence after `projects://changed` and browser
  `focus`, keeps the last rendered branch during refresh, ignores stale async
  results, and cleans up every listener on unmount.
- The unavailable Quick Note and keyboard-shortcuts controls remain keyboard
  reachable, explain their owning slices through tooltips, and invoke no command.
- All focused and repository-wide frontend checks, unchanged-backend checks,
  Rust checks, the Windows Tauri build, and the targeted manual Windows smoke
  check pass.

**Architecture:** `src/lib/ipc/projects.ts` is the shared typed adapter over the
existing `BE-003` commands and event. `src/features/home/` owns presentation and
temporary async state through two local hooks; it stores only project presence,
never a project list or durable business state. `src/app/app-router.tsx` consumes
only the public `HomeRoute` entry and retains the existing shell, route table,
breadcrumb metadata, and error boundary.

**Tech Stack:** React 19.2.8, TypeScript 7.0.2, React Router 8.3.1, Tauri API
2.11.1, Tailwind CSS 4.3.3, shadcn/ui source components, Radix UI tooltip through
the existing `radix-ui` 1.6.7 package, Lucide React 1.39.0, Vitest 4.1.11, and
Testing Library.

## Scope

**In Scope:**

- A typed shared wrapper for `list_projects`, `add_project`, and
  `projects://changed`, using the generated Projects DTOs and the existing
  `IpcCallError` conversion.
- Project-presence loading, refresh, stale-result protection, failure
  classification, and listener cleanup local to the mounted Home route.
- The responsive Welcome layout, decorative inline SVG, loading and load-error
  states, temporary Home placeholder, and all accessibility behavior documented
  by `FE-002`.
- The complete first-project add flow, including native picker cancellation,
  successful and duplicate-project navigation, retryable messages, terminal
  integration failure, duplicate-call prevention, and focus restoration.
- Replacing only the index route's `element` with `HomeRoute` and updating its
  component test while retaining the `Home` breadcrumb and every other route.

**Out of Scope:**

- The real Home dashboard (`FE-003`), Projects page and sidebar project list
  (`FE-004`), Project Overview (`FE-005`), Quick Note (`BE-017`/`FE-020`), and
  keyboard-shortcuts page or bindings (`BE-009`/`FE-014`).
- Project searching, display, rename, pin, open, locate, removal, availability
  presentation, or any frontend-owned project cache/store.
- Dark theme, font-size settings, animation, and the inactive shortcut hint from
  the wireframe.
- Any Rust, migration, generated binding, Tauri capability, Tauri configuration,
  dependency, or package manifest change.
- Automated desktop end-to-end tests and macOS validation.

## Global Constraints

- Write code, identifiers, and code comments in English; the initial UI copy is
  English and must match `FE-002` exactly.
- React owns presentation and temporary UI state. Rust remains the source of
  project data, persistence, native folder selection, and business rules.
- Every backend call passes through `src/lib/ipc/`; components do not call Tauri
  or operating-system APIs directly.
- `src/app/` may import only the public `HomeRoute` entry from the feature.
  `src/features/home/` must not import implementation from `src/app/` or another
  feature, and `src/lib/` must not depend on `src/features/` or `src/app/`.
- `HomeRoute` replaces only the index route `element`; the route remains `/`, its
  breadcrumb remains `Home`, and all other route elements and metadata remain
  unchanged.
- Use `ProjectDto`, `ProjectFolderSelectionDto`, `ProjectChangedEventDto`, and
  `ProjectsError` from `src/bindings/projects/projects.ts`; never hand-write or
  manually edit a backend DTO or error union.
- Treat `projects://changed` only as an invalidation signal. Re-query
  `list_projects`; do not derive presence from `change` or `projectId`.
- Keep presence and Add Project state in memory only. Add no `localStorage`,
  `sessionStorage`, `indexedDB`, cookie, or shared project-list store.
- Keep the last successful `empty` or `present` branch mounted during refresh;
  do not move focus or flash the first-load state. Only the latest request may
  update state, including after unmount.
- Do not auto-focus `Add Project` on mount. The content focus order is
  `Add Project`, optional error action, `Open Quick Note`, then
  `See keyboard shortcuts`.
- Keep unavailable controls focusable with `aria-disabled="true"`; their handlers
  return without navigation or command calls, and their tooltips open on hover
  and focus.
- The inline `WelcomeArt` is decorative, non-focusable, `aria-hidden="true"`, and
  uses existing CSS color tokens instead of hard-coded color literals.
- Add no motion. At content widths below `900px`, use one column, hide the art,
  reduce horizontal padding from `96px` to `48px`, and keep all text and controls
  visible without clipping.
- Every new function, component, hook, callback, helper, and test has a short
  purpose comment. Complex invariants such as stale-result rejection and
  duplicate-call prevention receive concise reasoning comments.
- Add tests for every new behavior. Do not add or run automated desktop
  end-to-end tests. Normal development and native smoke validation are Windows
  only; macOS validation remains deferred to release preparation.

## Assumptions, Risks, and Blockers

**Assumptions:**

- `BE-003` is implemented and its committed generated file
  `src/bindings/projects/projects.ts` is current; this plan only consumes that
  contract.
- The phrase “all six reasons” in one `FE-002` completion item is a counting
  typo. The error table and generated union define seven
  `InvalidProjectFolderReasonDto` values, and the tests cover all seven:
  `notAbsolute`, `missing`, `notDirectory`, `fileSystemRoot`, `notUtf8`,
  `accessDenied`, and `cannotCanonicalize`.
- Existing `Button`, `Tooltip`, CSS tokens, and Lucide icons can express the
  Welcome design with feature-local classes; no shared primitive or theme-token
  change is needed.

**Risks:**

- A slower presence query could overwrite a newer event/focus refresh. Task 2
  uses a monotonically increasing request token and tests out-of-order
  completion, unmount, and listener cleanup.
- Tauri event listener registration is asynchronous, so unmount can race with a
  pending `listen` result. Task 2 tests that a late registration is immediately
  unlistened and cannot update React state.
- Native show-from-tray may not deliver browser `focus` on every Windows runtime
  path because `BE-001` exposes no explicit “main window shown” event. Task 4's
  smoke check records the actual behavior; `projects://changed`, route remount,
  and ordinary focus remain the specified refresh paths. A guaranteed native
  signal would require a future `BE-001` contract change and is not invented here.
- A folder picker temporarily removes browser focus, so cancellation can lose the
  initiating element. Task 3 retains a button ref and explicitly restores focus
  only after the `cancelled` result.
- `projectAlreadyExists` uses the generated snake_case field `project_id`, not a
  guessed camelCase name. Tasks 1 and 3 assert the raw payload and resulting
  navigation path.

**Blockers:** None.

## Deviations and Decisions

- **Two shell test files outside the planned file list had to change.**
  `src/app/app-shell.test.tsx` and `src/app/app-topbar.test.tsx` render the real
  router at `/`, so replacing the index element made them reach the unmocked
  Projects boundary. Both now mock `@/lib/ipc/projects` with one project, and the
  shell case that read the `Home` heading now awaits it, because the branch is
  resolved asynchronously. No production behavior of the shell changed.
- **The 900px breakpoint uses a container query, not a media query.** `FE-002`
  measures the *content* width, which is the viewport minus the sidebar, so
  `WelcomeScreen` marks its own root `@container` and uses `@min-[900px]:`
  variants. The generated stylesheet was checked to confirm Tailwind emits
  `@container (width>=900px)` for those classes.
- **`HomeRoute` derives the retry lock instead of holding an `isRetrying` flag in
  an effect.** It stores the presence object a retry started from and compares it
  by identity; every published presence is a fresh object, so the lock releases
  itself. The behavior the plan specified is unchanged, and this avoids a
  `useEffect` that Biome's `useExhaustiveDependencies` rejects.
- **`useAddProject` flushes the idle state before restoring focus.** The primary
  button carries the native `disabled` attribute while the picker is open, and a
  disabled element cannot take focus, so the cancellation path commits the idle
  status with `flushSync` before calling `onCancelled`.
- **Focused test commands were run as `pnpm exec vitest run <file>`.** In this
  workspace `pnpm test -- <file>` does not forward the path as a filter and runs
  the whole suite. Every named target was still discovered individually and again
  by `pnpm test`.
- **The manual Windows smoke check has not been run.** It needs an interactive
  desktop session with a clean database and a throwaway folder.
